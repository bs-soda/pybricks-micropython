## 1. The Socratic 5-Why Root Cause Chain

```text
Symptom: Re-running a robotics script or instantiating MDRobotBase fails with OSError: [Errno 16] EBUSY: Device or resource busy.
│
├── [Why 1] Why did the constructor fail with EBUSY?
│   └── pbio_mdrobotbase_get_robotbase() in lib/pbio/src/mdrobotbase.c scanned active slots, saw the motors were in use, and returned PBIO_ERROR_BUSY.
│
├── [Why 2] Why were the motors still marked as in use?
│   └── The previous robot instance holding those motors was never closed via pbio_mdrobotbase_put_robotbase().
│
├── [Why 3] Why was the previous instance not closed?
│   └── The previous script crashed on an unhandled exception (ETIMEDOUT), aborting execution before robot.close() could run.
│
├── [Why 4] Why didn't MicroPython garbage collection or the runtime clean up the orphaned native slot?
│   └── pb_type_MDRobotBase is registered with MP_TYPE_FLAG_NONE without a GC finalizer, and lib/pbio/src/main.c lacks an mdrobotbase deinit hook during application start/stop.
│
└── [Why 5] (Root Cause) Why does pbio_mdrobotbase_get_robotbase() treat an identical motor-pair re-allocation as a hostile conflict?
    └── The allocator did not distinguish between hostile partial overlap (stealing 1 motor) vs benign exact-pair re-entry (re-running the same robot configuration). It must safely re-bind exact pairs while continuing to block partial overlaps.
```

## 2. Quantitative Mathematical Bounds & Invariants

1. **Overlap vs. Exact Match Decision Matrix:**
   $$\text{Overlap}(L_1, R_1, L_2, R_2) = (L_1 = L_2 \lor L_1 = R_2 \lor R_1 = L_2 \lor R_1 = R_2)$$
   $$\text{ExactMatch}(L_1, R_1, L_2, R_2) = (L_1 = L_2 \land R_1 = R_2)$$

2. **Allocation Action Formulation:**
   $$\text{Decision} = \begin{cases}
   \text{Rebind Slot and Return Success}, & \text{if } \text{ExactMatch} \\
   \text{Return } \text{PBIO\_ERROR\_BUSY}, & \text{if } \text{Overlap} \land \neg\text{ExactMatch} \\
   \text{Allocate from Free Pool}, & \text{otherwise}
   \end{cases}$$
